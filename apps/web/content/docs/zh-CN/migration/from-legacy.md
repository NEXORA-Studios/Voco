# 旧数据迁移

Voco 内置了针对旧版 YAML 应用数据目录的一次性迁移。这不是用户手动启动的向导，而是在应用初始化时自动执行，将受支持的旧设置、词汇包、分类和随机抽取器预设转换为当前 TOML 格式。

## 何时执行

当应用数据目录存在 `settings.yml` 且不存在 `settings.toml` 时，迁移会执行。如果 `settings.toml` 已存在，则跳过这项旧版迁移。若以上条件不满足，Voco 不会自动推断或转换其他文件。

## 转换内容

- `settings.yml` 转为 `settings.toml`。存在旧界面语言时保留；否则使用 `en-GB`。新增设置采用当前默认值。
- `packages/bundles/*.yml` 转为设置中的分类标签定义，并根据旧分类关系恢复词汇包归属和顺序。
- `packages/source/*.yml` 转为含 `package.toml` 和 `data.toml` 的词汇包目录。
- 若存在 `picker/presets.yml`，则转为 `picker/presets.toml`。

旧词条可保留 ID、原文、译文和支持的顺序信息。旧数据不包含当前格式的原文说明、译文说明或词汇包图片，因此迁移不会重建这些内容。旧词汇包也没有源语言和目标语言信息，因此会设为 `und`。

## 备份和清理

转换前，Voco 会将应用数据目录中的文件复制到 `backups/migration-data-format/` 下的带时间戳目录，并逐个校验文件大小和 SHA-256 校验和。成功后该备份仍会保留。备份过程跳过现有 `backups` 目录和以点开头的条目。

转换和验证成功后，Voco 会删除旧 YAML 设置、分类、词汇包和预设文件。迁移清单和报告仅为临时文件，成功后会删除；长期保留的恢复来源是时间戳备份目录。

## 迁移失败时

迁移失败后，数据存储会拒绝正常读写操作。当前应用没有设计稿中提到的“从零开始”或“提交 Issue”选项，也不会自动从备份恢复。失败前可能已经写入部分新格式文件。

请勿删除或手动修改应用数据目录及时间戳备份。保留错误信息和整个数据目录，联系项目维护者获取恢复建议。不要假定重新安装应用可以修复或回滚数据。

## 更新旧版安装

如果仍能打开使用 YAML 格式的旧版本，请在启动包含该迁移的版本前，额外复制一份应用数据目录。内置迁移会自行备份，但独立副本可增加一个恢复点。不要手动把 YAML 文件改名为 TOML；两种格式和目录结构不同。

## 适用范围

以上说明的是已实现的旧版 YAML 到 TOML 迁移，不是任意旧词汇包格式的通用导入器。当前应用没有手动迁移或恢复界面。
