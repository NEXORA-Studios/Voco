# 舊資料遷移

Voco 內建舊版 YAML 應用程式資料目錄的一次性遷移。這不是由使用者手動啟動的精靈，而是在應用程式初始化時自動執行，將支援的舊設定、詞彙包、分類和隨機抽選器預設轉換為目前的 TOML 格式。

## 何時執行

當應用程式資料目錄存在 `settings.yml` 且不存在 `settings.toml` 時，遷移會執行。若 `settings.toml` 已存在，則略過這項舊版遷移。若以上條件不成立，Voco 不會自動推斷或轉換其他檔案。

## 轉換內容

- `settings.yml` 轉為 `settings.toml`。若有舊介面語言則保留，否則使用 `en-GB`。新增設定欄位採用目前的預設值。
- `packages/bundles/*.yml` 轉為設定中的分類標籤定義，並依舊分類關係還原詞彙包歸屬與順序。
- `packages/source/*.yml` 轉為包含 `package.toml` 和 `data.toml` 的詞彙包目錄。
- 若存在 `picker/presets.yml`，則轉為 `picker/presets.toml`。

舊詞條可保留 ID、詞彙、翻譯和支援的順序資訊。舊資料不包含目前格式的簡介、簡介翻譯或例圖，因此遷移不會重建這些內容。舊詞彙包也沒有來源語言和目標語言資訊，因此會設為 `und`。

## 備份與清理

轉換前，Voco 會將應用程式資料目錄中的檔案複製到 `backups/migration-data-format/` 下含時間戳記的資料夾，並逐一驗證檔案大小和 SHA-256 校驗碼。成功後該備份仍會保留。備份程序會略過既有的 `backups` 資料夾和以句點開頭的項目。

轉換和驗證成功後，Voco 會刪除舊 YAML 設定、分類、詞彙包和預設檔案。遷移清單和報告只是暫存檔，成功後會刪除；保留作為復原來源的是含時間戳記的備份資料夾。

## 遷移失敗時

遷移失敗後，資料儲存層會拒絕正常讀寫。目前應用程式沒有設計稿提到的「從零開始」或「提交 Issue」選項，也不會自動從備份還原。停止前可能已寫入部分新格式檔案。

請勿刪除或手動修改應用程式資料目錄及含時間戳記的備份。保留錯誤訊息和完整資料目錄，聯絡專案維護者尋求復原建議。不要假設重新安裝應用程式就能修復或回復資料。

## 更新舊版安裝

若仍可使用採用 YAML 格式的舊版，請在啟動包含此遷移功能的版本前，另外複製一份應用程式資料目錄。內建遷移會自行備份，但獨立副本可提供額外復原點。請勿手動將 YAML 檔案重新命名為 TOML；兩種格式和資料夾結構不同。

## 適用範圍

以上說明的是已實作的舊版 YAML 至 TOML 遷移，不是任意舊詞彙包格式的通用匯入器。目前應用程式沒有手動遷移或還原介面。
